# Latency

实习期间的网络时延相关 Qt/C++ 项目源码，保留了原有的多个工程目录。

| 目录 | 内容 |
| --- | --- |
| `project_B/` | 包含转发模块的 Qt 工程（`projectB.pro`） |
| `receiver_window/` | 接收端 Qt 工程（`receiver_window.pro`） |
| `TSM/`、`TSM1/` | 发送端和控制器的两个工程版本（`two_process_sender.pro`） |
| `test_build_0712/` | 原有的源码检查脚本；脚本中保留了旧机器的绝对路径，运行前需调整 |

可以在 Qt Creator 中打开对应的 `.pro` 文件。工程使用 Qt 的 Core、GUI、Widgets、Network、Charts 等模块，部分代码需要 Concurrent 模块。`build/` 目录和 `.pro.user` 文件是本机生成内容，未纳入版本控制。

## 文件传输

在发送端选择文件并发送，接收端收到完整文件后会启用“保存文件”按钮；多个已完成文件按完成顺序逐个保存。接收端将文件头（包类型 `2`，含文件大小和名称）与文件数据片（包类型 `1`）按批次和序列号重组，先写入临时文件，确认分片数与字节数都正确后才允许保存。发送端 `TSM/` 与 `TSM1/` 均需使用更新后的协议重新构建。

TCP 模式支持连接断开的不完整传输清理。UDP 模式可以重排已到达的分片；当前协议没有丢失分片的重传机制，缺片时不会将文件标记为完成。等待缺片时最多缓存 64 MiB 数据。

建议在 Qt Creator 中依次验证空文件、大小刚好为分片大小整数倍的文件、跨优先级乱序的文件，以及 UDP 丢失一个分片的情况。前三种应能保存并与原文件逐字节一致；最后一种应保持未完成状态。

## 发送速率

发送端 `TSM/TSM_Controller` 和 `TSM1/TSM_Controller` 默认使用“目标速率”，单位为十进制 Mbps（1 Mbps = 1,000,000 bit/s）。速率按实际协议包字节数计算；TCP 还计入每包的 4 字节长度前缀。需要复现旧实验时可切换到“固定间隔”。同一个调度器控制普通测试包和文件分片，并限制待发队列以及 TCP 写缓冲。发送完成后显示实际入队平均速率；它可能低于目标值，受定时器精度、CPU、网络和接收端处理能力影响。

A、B、C 端批次反馈中的“处理耗时”累计逐包本地生成、发送或处理时间，不把限速造成的包间等待计入处理耗时。A 端另在状态栏显示包含限速等待的整批入队耗时。三端应一起重新构建，反馈包格式保持不变。
